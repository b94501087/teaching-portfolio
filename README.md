# yuchuntsai.com — teaching portfolio

Static site on GitHub Pages. Pages are rendered from `content/*.json` at deploy time
(`.github/workflows/pages.yml` runs `node build/build.mjs` and publishes `_site/`).

| URL | Source |
| --- | --- |
| `/` | landing page: name + links (name and link labels from `content/site.json`; layout fixed) |
| `/board/` | pin board — `content/board.json` (+ shards listed in its `shards` key, e.g. `content/board-2.json`; merged in order by `mergeBoard`) (template in `admin/render.js`, CSS `style.css`) |
| `/board/<slug>/` | one detail page per visible pin: title, optional description, up to 10 images (first = board cover). Optional `sections` (`heading`, `body`, `images` picked from the pin's images, one-line `captions`) switch the page to one centred column: text then images at the same width, every image in the same 4:3 box. Optional translations in `i18n` (pin: `title`, `description`; section: `heading`, `body`, `captions`) for the languages in `LANGS` (`admin/render.js`; English, 繁體中文, and 简体中文 via OpenCC) add an EN / 繁中 / 简中 switch that remembers the visitor's choice. The page opens in 繁體中文; `?lang=` and the saved choice still override. Empty translated fields fall back to English. `draft: true` publishes the page at its URL for preview (marked noindex) without listing it on `/board/`; `visible: false` hides it completely |
| `/A-Z/` | A–Z index — `content/az.json` (letters grouped automatically); `/a-z/` redirects here |
| `/teaching/` | teaching page — `content/teaching.json` |
| `/consulting/` | price list — `content/consulting.json` |
| `/cv/`, `/A-Z/*.html` | static pages (`{{name}}` / `{{email}}` filled from `content/site.json`) |
| `/blog/`, `/blog/<slug>/` | blog — `content/blog.json` (template `admin/blog.js`). Index with category filters (`#cat=<id>`: `school-selection`, `portfolio-strategy`, `essay`, `dream-school`, `top-school`; a post may have several), newest first; empty state 「即將上線」 while `posts` is empty. `#saved` on the index is the local 收藏清單 (no new URL). Each post is pre-rendered static HTML: H1, TL;DR box (`tldr`), body (trusted HTML, H2s phrased as questions), optional FAQ (`faq: [{q,a}]` → FAQPage JSON-LD), author box (→ /cv/, /board/), related posts by category, BlogPosting + BreadcrumbList JSON-LD, canonical, OG/Twitter, hreflang when an `en` title+body exist (EN / 繁中 / 简中 switch). Posts also have a read count, like, bookmark, share bar, email subscribe box, and an RSS/Atom link. Counts come from the public Worker in `worker/engage/` (`ENGAGE_API` in `admin/blog.js`); they stay hidden if that API is down. `draft: true` = built with noindex, not listed. Field reference: header comment of `admin/blog.js` |
| `/sitemap.xml`, `/robots.txt`, `/blog/feed.xml`, `/llms.txt`, `/llms-full.txt` | generated by `build/build.mjs` (`admin/blog.js`): sitemap of every public page (drafts excluded; lastmod = post date / build date), robots allowing search + AI crawlers (GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, PerplexityBot, Google-Extended, Googlebot, Bingbot, Applebot-Extended, CCBot, …), Atom feed, llms.txt site/author summary |
| `/admin/` | editor with live preview; saves through the Worker in `worker/` (behind Cloudflare Access) |
| `yuchuntsai.com/engage/*` | public engagement API (not a Pages file): `worker/engage/` — D1 counts, likes, bookmarks, subscribers. Deploy steps in `worker/engage/README.md`. Not behind Access |
| `/pins/` → `/board/`, `/a-z/` → `/A-Z/`, `/ksteinfe/*` | redirect stubs to the new paths |

GitHub Pages cannot send an HTTP 301 for one path. `/pins/`, `/a-z/`, and `/ksteinfe/*` stay HTML stubs: a meta refresh, a visible link, and `<link rel="canonical">` to the target. They are omitted from `sitemap.xml` (`SITEMAP_SKIP_RE` in `admin/render.js`). A real 301 would need an edge in front of Pages, such as a Cloudflare redirect rule.

`/board/` paints the first screen of cards in the HTML, then loads `/board/cards.json` and appends the rest in the same order. CSS columns still run top to bottom. The file is data, not a page, so it is not in the sitemap.

Site-wide name, nav labels and contact email: `content/site.json`.
Fonts, colours, spacing, radius and column count live only in the CSS files and are not editable from /admin.

The build adds `?v=<hash of style.css>` to the root stylesheet link so returning visitors get new CSS.

Local preview: `node build/build.mjs && cd _site && python3 -m http.server`.

## Blog posts from WeChat articles

WeChat (mp.weixin.qq.com) images are hotlink-protected (`mmbiz.qpic.cn` returns a placeholder on other sites),
so every image must be downloaded and re-hosted under `assets/blog/<slug>/` (WebP, ≤270 KB like board images);
`validateBlog` rejects posts that still reference `mmbiz.qpic.cn` / `qpic.cn`. Steps:

1. Save the article (URL or saved HTML) and convert it with the local tool (outside this repo):
   `python3 /workspace/career/cms/wechat2blog.py <url-or-file.html> --slug <slug> --categories essay,school-selection`
   — downloads the images with a WeChat Referer, writes `assets/blog/<slug>/NN.webp`, cleans the body HTML
   (keeps h2/h3/p/ul/ol/li/blockquote/figure/img/a/strong/em/table) and prints a `posts[]` entry with
   `"draft": true` and `source: { type: "wechat", date }`.
2. Paste the entry into `content/blog.json`, edit: zh/en `title`, `summary` (1–2 sentences), `tldr` (direct
   answer), H2s as questions, `keywords`, optional `faq`; remove names of students; then drop `"draft": true`.
3. `node --test tests/ && node build/build.mjs`, check `/blog/<slug>/` locally, push.

Student works: match each student image against board pins (title + image similarity). If matched, show it as a `.post-work` card inside a `.work-grid`, reusing the pin image (`../../assets/board/<slug>/…`), with a caption (project title, school if the source says so, never a student name) and a 「看完整作品：<title>」 link to `../../board/<slug>/`. If not matched, do not guess a link; keep the cleaned local image and list it for the owner. Add official requirement facts with links and an "as of" date, plus an optional `abstract_en` (~120 words).
